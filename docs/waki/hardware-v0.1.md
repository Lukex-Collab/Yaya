# 瓦奇 Waki：硬件 V0.1 规格与采购底稿

日期：2026-10-09。用途：验证原型与采购筛选，尚非量产规格或最终 BOM。

## 1. 本轮需求与假设

- 品牌：瓦奇 / Waki；Yaya、牙牙、芽芽为历史名称。
- 用户已明确要求：GPS 定位、摄像头。
- 暂定验证场景：脱离手机的户外联网、位置上报、用户主动拍照问答、语音陪伴。
- 摄像头暂按单张 JPEG 上传设计。持续视频、远程实时查看尚未确认；若需要，两者会显著改变带宽、处理器与续航设计。
- 位置指瓦奇设备的位置。挂件与人分离后，不能把设备位置当作人的位置。
- 不立即改动历史仓库，不立即开模或做最终 PCB。

## 2. 已有基线与重要修正

此前源码显示 ESP32-S3 N16R8、INMP441、MAX98357A 和 OV5640 的原型代码。代码存在不代表当前实物库存、接线和功能全部已验证，采购前先点验。

语音程序、摄像头测试与推流程序目前是不同原型，不能假定能够并发运行。现有语音走局域网 HTTP，尚未证明脱离电脑、使用公网服务器和 4G 后能够工作。

GPS/GNSS 负责计算位置；4G 或 WiFi 负责上传位置。室内和遮挡环境可能无法获得卫星定位。界面必须区分当前有效定位、过期位置、定位失败，不显示伪造的实时位置。

上一轮提到的具体 AI 玩具市场热度没有完成实时来源核验；本文不据此给出销量、拆机配置或最新价格结论。不同 AI 玩具路线不能作为同一硬件 BOM。

## 3. 建议原型架构

```text
带保护的单节锂电池 / 台架电源
  -> 带电源路径管理的供电系统
     -> ESP32-S3 + 麦克风 + 摄像头
     -> 功放 + 扬声器
     -> 独立适配的 4G 模块电源

GNSS 模块 -- UART --> ESP32-S3
摄像头 -- DVP --> ESP32-S3 -- WiFi / 4G --> 公网服务
麦克风 -- I2S --> ESP32-S3 <-- 回复音频 -- 公网服务
按键 / 镜头滑盖 / 状态灯 --> 用户控制与反馈
```

4G 通信优先验证 ESP32-S3 通过 PPP 取得 IP、复用网络客户端的路径；也可以采用模块 AT HTTP/TLS，但须先确认二进制上传、TLS 和音频下载能力。两种路径先选一条打通，不同时实现。

## 4. 第一轮采购清单

| 项目 | 数量 | 采购要求 | 顺序 |
|---|---:|---|---|
| ESP32-S3 N16R8 开发板 | 现有板 + 1 块备用 | 明确 16MB Flash、8MB PSRAM，提供原理图及可用引脚表 | 有现成可工作板则仅补备用 |
| GNSS 开发板 | 1 | L76K 或同级 GPS/北斗板，包含匹配天线；明确供电与 UART 电平，提供 NMEA 示例 | 第一轮 |
| 4G Cat.1 开发板 | 1 | 国内频段适配的 EC200U-CN 系列候选；购买完整板，附 LTE 天线、SIM 卡座、供电及 ESP32 通信示例 | 第一轮，核对具体料号后购入 |
| 流量 SIM 卡 | 1 | 允许目标设备和目标服务联网；明确流量、续费及网络限制 | 与 4G 板同步 |
| 摄像头 | 先复用 OV5640 | 先在现有测试链路上验证 JPEG；若不稳定再买有官方示例的 ESP32-S3 摄像头套件 | 先测试再决定补购 |
| INMP441 + MAX98357A | 各 1 套备用以内 | 优先复用已有音频器件；不要因增加 GPS 而重买全部语音器件 | 按库存补购 |
| 扬声器 | 现有 + 1 个对照 | 记录阻抗、额定功率、尺寸和灵敏度；3W 是额定值，不表示电池条件下可输出 3W | 结构验证时 |
| USB 功耗表 | 1 | 用于快速观察输入功耗；不能替代低功耗或瞬态测量 | 第一轮 |
| 可调台架电源 | 1，若无现成设备 | 电压、电流能力按 4G 开发板手册选择，留瞬态余量 | 第一轮 |
| 按键、状态 LED、镜头遮挡件、短线、固定件 | 1 批 | 能触发拍照、清楚显示采集状态，并固定镜头朝向 | 第一轮 |

建议搜索关键词：`L76K GNSS 开发板 天线 NMEA`、`EC200U-CN Cat1 开发板 ESP32 PPP 原理图`。关键词仅用于筛选，具体商品页面仍须通过下列检查。

采购前必须向卖家确认：

1. GNSS 是否真实包含卫星定位接收器及匹配天线，而不是仅提供基站定位。
2. 4G 的完整模块料号、固件版本、国内频段、SIM 支持与 GNSS 配置。系列名字不能证明带 GNSS。
3. 模块与开发板 UART 电平。裸模块可能使用 1.8V，ESP32 为 3.3V；确认开发板是否已做电平转换。
4. 电源输入电压、发射峰值电流、稳压与电容要求，是否支持所选电池接入方式。
5. 是否能用 ESP32 上传 JPEG/PCM 并下载音频；确认 PPP 或 AT 命令示例、TLS 支持。
6. 相机排线接口、针脚和传感器驱动是否匹配。相同针数不等于可以互插。

若所选 4G 板已确认包含可用 GNSS、天线及示例，则取消独立 GNSS 板，减少重复采购。

## 5. 电池与供电：台架通过后购买

- 先以 2000-3000mAh 单节锂电池作为测试容量候选；最终容量由壳体尺寸、重量和实测决定。
- 电池须有明确保护、最大持续/脉冲放电能力和 NTC 配置；接口相同也要确认正负极。
- 选择带电源路径管理、充电电流可配置、适配电池保护与温度检测的电源板。BQ24074 系列可作为候选，仍需核对整板输出能力。
- 不把 IP5306 移动电源板直接等同于低功耗玩具 PMIC；部分板会因低负载自动关机。
- 3.3V 主电源需按电池完整电压范围选型，不能简单假定一个 LDO 可以一直稳定输出 3.3V。需要时使用升降压方案。
- MAX98357A 可在数据手册允许范围内用较低电压供电；先测试电池直供时的音量，再决定是否需要独立 5V 升压。
- 4G 裸模块 VBAT 与开发板输入电压不同，须按对应手册接线。禁止从 ESP32 小电流输出口给 4G 供电。
- TP4056 充电板不自动提供正确的边充边用管理；不能单凭带保护板就认定系统电源已完成。
- MAX17048 电量计与功耗测量板可在便携原型阶段增加。普通 USB 表看不到全部射频瞬态；异常复位时使用示波器或合适的功率分析仪查电源。

## 6. 分阶段验收

| 阶段 | 操作 | 建议通过条件 |
|---|---|---|
| 现有器件点验 | 记录型号、接线、供电与现存代码 | 明确哪项有实物、哪项只是代码；有一套可复现语音基线 |
| GNSS | 开阔户外冷启动并记录 NMEA | 多次取得有效 fix，保留时间、卫星数、定位质量；实际地图位置可核对 |
| 4G | ESP32 访问公网测试端点 | 脱离电脑局域网后成功上传与下载；掉网后恢复，不造成持续复位 |
| 摄像头 | 按键拍照、上传、视觉问答 | 先验证 640x480 JPEG 是否满足场景；连续 50 次触发无复位、图像可辨认 |
| 综合台架 | 拍照上传、语音、位置上报交替运行 | 至少 1 小时，无异常重启或持续内存下降；记录失败和延迟 |
| 便携原型 | 电池供电、挂包行走、装入毛绒 | 记录遮挡、天线朝向、温升、拾音、重量和实际续航，再确定主板 |

上述次数与时长是建议验收起点，不是已实现指标或量产可靠性测试。

## 7. 暂定工作策略

- 摄像头：主动触发单张拍摄，闲时关闭或待机；用匹配供电控制和上电时序实现，检查 GPIO 反向供电问题。
- 位置：静止时降低频率；移动时可以先试 30-60 秒上报一次；用户主动查看时请求新位置。策略须同时验证功耗与找回体验。
- 语音：先完成可靠的按键或唤醒后对话，再评估常听。拍照与语音任务需协调 PSRAM、DMA 和网络资源。
- 前端：显示定位时间、有效性和离线状态；SOS 显示真正的送达/失败结果。
- 续航：先以 8 小时随身间歇使用作为试验目标，写清对话、拍照和上报次数；测试前不承诺续航。
- 相机用途：先验证拍照识物和共同经历记录。若用户要求实时视频，重新评估架构，不直接沿用本版。

## 8. 瓦奇当前最需要补齐的能力

1. 户外通信：局域网语音原型尚未成为独立联网设备。
2. 供电：缺少峰值电流、分状态功耗与温升测量，无法确定电池与尺寸。
3. 联合运行：摄像头、语音、定位、4G 尚未有并发验证证据。
4. 可感知反馈：明确正在听、正在拍、上传成功、离线，用户才能信任设备。
5. 结构：麦克风孔、扬声器腔体、镜头朝向和 LTE/GNSS 天线净空需要实物测试。
6. 公网服务：设备身份、TLS、配网、重连、OTA 与真实消息投递尚待完善。

触摸、压力、IMU 和震动值得后续验证，但本轮只需先用实体按键闭环。暂缓加热、屏幕、运动机构和批量 PCB。

## 9. 成本与预算边界

旧资料中的售价 299 元和落地成本 106 元没有覆盖本次完整需求，不能继续当作已验证商业结果。加入 4G/GNSS 后须重新计入天线、SIM 流量、电池、电源、结构、测试及售后。

采购执行方式：现有件复用；只补一套定位/联网台架；取得实际商品规格和报价后算总额。本文不提供未核验的最新市场价格，也不把开发板零售成本等同于量产 BOM。
